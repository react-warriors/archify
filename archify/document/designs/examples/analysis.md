# 预索引更快，但代价是更高的内存占用

检索路径对照实验 · 以下为虚构演示数据；文中结论仅对应这组示例。

## 观察：延迟改善与资源成本同时增加

> 预索引将示例中的 P90 延迟降至 42 毫秒，同时把内存占用提高到 188 MB。是否采用，取决于服务的内存预算。

| 方案 | P90 延迟（毫秒） | 内存占用（MB） |
| --- | ---: | ---: |
| 顺序检索 | 160 | 32 |
| 热点缓存 | 78 | 96 |
| 预索引 | 42 | 188 |

这两个指标使用不同单位，应该分开比较，不能放到同一根数值轴上。

## 实验条件：哪些输入固定，哪些范围还没有覆盖

| 观察对象 | 已固定的条件 | 此次未覆盖的条件 |
| --- | --- | --- |
| 查询集合 | 三种方案使用相同的查询集合，保持输入一致 | 新出现的长尾查询与不同业务的查询分布 |
| 数据规模 | 使用同一份数据快照，分别记录内存与延迟 | 持续更新的数据、维护时间与内存峰值 |
| 运行环境 | 每轮包含冷启动与重复查询，采用相同计时口径 | 其他机器配置、并发请求与长期运行的资源变化 |

这些条件限定了记录的适用范围。关系图表达同一行中对象与条件的对应关系，不把固定条件解释成因果结论。

## 方法：固定输入，只改变检索路径

- 三种方案使用同一组查询和同一个数据集。
- 每轮测试包含冷启动与重复查询。
- 分别记录延迟、内存和错误数量。

```js
for (const query of queries) {
  measurements.push(await run(query));
}
```

## 不确定性：冷热比例可能改变结果

| 热点查询比例（%） | 缓存方案延迟（毫秒） | 预索引延迟（毫秒） |
| --- | ---: | ---: |
| 20 | 126 | 49 |
| 50 | 92 | 45 |
| 80 | 61 | 42 |
